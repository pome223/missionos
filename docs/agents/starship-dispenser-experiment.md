# 放出詰まりの有限モデル比較契約

## 事前固定した範囲

2026-10-03に比較結果を選ぶ前に固定した合成サブシステム試験。
Flight 14の再現モデル、Starlinkの実機放出装置、運用上の回復確率を変更・同定するものではない。
放出後の衛星分離、軌道投入、通信サービス、機体の帰還成功はこの試験の終端判定に含めない。
LLM呼出し、実機接続、クラウド実行は行わない。

| 項目 | 固定値・意味 |
| --- | --- |
| 時間 | 2秒刻み、開始0秒、作業期限24秒。実測の宇宙機時刻ではない |
| ペイロード | 試験専用3個、初期放出0。1回の成功で1個を放出する |
| 行動 | `wait` 2秒、`retry` 4秒、`abort` 即時終了 |
| 試行上限 | 最大5回。成功・失敗とも1試行を消費 |
| 回復時刻 R | 4、8、14、18秒、回復なし。確率は順に1/6、1/6、1/6、1/6、1/3 |
| 観測 | ready表示の確率は回復済みなら0.8、未回復なら0.15 |
| 終了条件 | 3個放出、明示的中止、期限、または許可できる試行なし |
| 目的関数 | `10 × released_count − 0.15 × elapsed_s − attempt_count` |
| 燃料 | 未モデル化。時間・試行の費用は研究用の効用であり燃料量や実損傷ではない |

放出の成否は**試行開始時**に `R <= start_time` かで決まり、receiptは4秒後に出る。
開始時点では詰まり、終了時点ではセンサーがreadyを示すこともある。
行動終了が24秒ちょうどなら許可し、超過する行動はRulesが拒否する。
この期限は合成の作業枠であり、地理的に有効な帰還windowを計算したことにはならない。
待機中も時計は進む。軌道や推進剤をこのfixtureで積分したとは主張しない。

目的関数はこの有限試験の比較用に固定する。放出数、期限遵守、残り時間、試行数は
効用にまとめる前の値も別々に保存する。評価結果を見て重みや故障分布を変更しない。

## 同じ開始条件・観測・故障系列

各worldは回復時刻と全2秒gridのセンサー系列を方針の実行前に生成し、内容hashを保存する。
系列は絶対時刻に結び付ける。方針の試行回数で乱数を消費して別世界を作らない。
同一worldを全方針に渡すが、方針の入口にはworld自体を渡さない。

方針に見せるのは公開した予算・時刻・過去の試行receipt・取得済みセンサー履歴だけ。
センサー取得は開始0秒と各行動の終了時。行動中間のgrid値を後から開示しない。
world ID、種別、seed、実現したR、未取得センサー値は方針入力に含めない。
履歴ルールと分布既知方針は同じ事前分布・観測確率を知ってよい。

調整用はshort/late/never各10系列、評価用は各20系列。群はそれぞれ1/3で集計する。
short内はR=4/8、late内はR=14/18を各1/2で抽出する。
調整seedは101–110、評価seedは1001–1020で、群とsplitを含めて系列を識別する。
評価は**未使用の乱数実現**であり、未知の故障モデルや実機での汎化ではない。

## 方針と上限の区別

| 方針 | 調整前に固定した候補 |
| --- | --- |
| すぐ中止 | 即時 `abort` |
| 決まった回数の再試行 | 連続試行。上限1、2、3、4、5回 |
| 決まった間隔で待って再試行 | 初回と各試行後に2、4、6秒のいずれかを待つ。最大5回 |
| 履歴ルール | 観測履歴から回復済みの事後確率を更新。閾値0.25、0.5、0.75以上なら試行、未満なら待機 |
| 分布既知の最良方針 | 同じ観測からのbelief、時間、残数、試行数を使う有限Bellman最適化 |

候補のある3方針は調整系列の平均効用で選び、同点は上表の列挙順で決める。
評価前に選択を固定し、評価の結果で選び直さない。
履歴ルールも分布を知るため、分布既知方針だけに有利な知識を与えた比較にしない。

Bellmanはretry開始時の成否と終了時センサーの両方でbeliefを更新する。
宣言した有限分布・観測・行動・効用に対する**期待効用の最適値**である。
任意の宇宙機方針の上限や、評価サンプルの各worldで最良になる保証ではない。

実現Rを知るclairvoyantは参考上限として別に置き、実行時に達成可能な改善量と呼ばない。
事後に最良だった方針をworldごとに選ぶ値も、観測可能な方針の性能には数えない。
有限モデルの期待値と、60件の評価系列の標本平均を区別する。

## 実行と検証の境界

`observation → typed proposal → simulation scope → Rules → executor receipt → verifier`
を別記録にする。simulation scopeは合成実験の許可であり、実運航者の認証や飛行承認ではない。
Rulesは期限・試行予算・残ペイロードを制約し、拒否された提案を放出済みにしない。
保存記録を別のverifierで走査し、入力結合、観測、行動時間、成否、放出数、費用、終端を照合する。
記録検証の合格を、実機の故障回復・衛星サービス・ミッション完了に昇格させない。

## 止めどころ

今回の成果は、同じ条件で方針を実行して終端を比較できる仕組みと、その比較結果。
候補が同じ結果になる、または履歴を使う単純方針で十分なら、その負の結果を残す。
分布既知方針との差が残っても、直ちにLLMの価値を示したとはしない。
文字情報の追加がLLMを必要にするという主張も未検証の仮説である。
新たな故障条件・テキスト入力・LLM接続は、この比較とは別の実験として定義する。

## 再現入口

```sh
python scripts/run_starship_dispenser_experiment.py --approve-synthetic --output-dir output/starship-dispenser-study
python scripts/run_starship_dispenser_experiment.py --verify output/starship-dispenser-study/study.json
```

既存出力は上書きしない。`--approve-synthetic` がなければ実行せず、出力directoryも作らない。
結果は `study.json`、独立走査は `verification.json`、閲覧用は `report.html`、ファイル結合は
`manifest.json` に保存する。調整候補の実行記録も含め、選ばれなかった結果を残す。
provenanceのsource hashは実行時ファイルへの結合であり、署名や外部の真正性保証ではない。
保存結果のverifyは新たな乱数世界やLLM呼出しを作らず、記録の意味を再計算する。

テスト入口:

```sh
PYTHONPATH=packages/missionos-core/src:. python -m pytest -q tests/contract/test_starship_dispenser*.py
```

検証結果と有限モデル内での比較は[人向けの実験記録](../examples/starship-dispenser-experiment.md)に分ける。
