# Artifact Taxonomy

MissionOS should make evidence easy to audit. Each artifact category below names
its authoritative schema and the code that owns it. Prefer these exact shapes
over ad hoc dicts.

## Task Record

`TaskRecord` in `src/gateway/api_schema.py` (`model_config = extra="forbid"`) is
the durable object for status and outcome. Key fields: `task_id`, `kind`,
`title`, `status`, `artifacts: dict`, `metadata: dict`, `approval_dependencies`,
`run_id`, `winner_task_id` / `loser_task_ids`, `error`, and the timestamps
`created_at` / `updated_at` / `started_at` / `ended_at`.

Records are persisted by `TaskStore` (`src/runtime/task_store.py`), a
SQLite-backed store (`data/tasks.db`). Runtime evidence is attached under
`artifacts`, keyed by producer (for example `missionos_hardware_adapter_evidence`,
`missionos_auto_mission_runtime_replay`). Do not overwrite prior proposal or
approval facts when appending new artifacts.

## Timeline

`TaskTimelineEntry` in `src/gateway/api_schema.py` is ordered evidence. Each
entry has `timeline_id`, `timestamp`, `event_type`, `status`, `summary`, and a
`kind` ∈ `task_event | approval | audit` that identifies which boundary produced
it. Structured detail rides in `payload` / `task_event` / `approval` /
`audit_focus`. Timeline order is the audit trail; keep it append-only.

## Runtime Snapshot

Runtime snapshots describe observed simulator or hardware state and are
read-only. The TurtleBot3 telemetry sidecar model
(`src/runtime/turtlebot3_telemetry_sidecar.py`) is the reference shape: it pins
`read_only=True`, `command_surface_present=False`, `ros_dispatch_allowed=False`,
`physical_execution_invoked=False`, and `mission_delivery_completion_claimed=False`.
Treat stale, missing, or partial snapshots as limited evidence, not completion.

## Map Artifact

A map artifact is an HTML evidence surface generated by the CLI
(`_write_mission_map_html` in
`packages/missionos-cli/src/missionos_cli/cli.py`, output under
`output/missionos_maps/<task>_<time>.html`). It displays route, location,
telemetry, or replay data and is explicitly "read-only evidence display, not a
verifier, dispatch control, or delivery claim." Never treat a rendered map as a
verifier verdict.

## Fixture Artifact

Fixture artifacts are public-safe sample records served by the fixture Gateway
(`packages/missionos-gateway/src/missionos_gateway/server.py`, e.g.
`FIXTURE_TASK_ID = "task_fixture_delivery"`, kind `missionos_fixture_runtime`).
They must be deterministic, small, and free of private paths or credentials, and
must not be presented as a live run.
