## Authority-gap reasoning follow-up

The `e9ec7219` four-flight protocol stopped after its first role. The scope
flight's final record was signed and independently consistent, but it ended
`return_unresolved`: Jev returned valid decisions without requesting an
amendment. The original request deadline was visible; a final pre-expiry wake
occurred. This is not the earlier deadline-visibility defect. The other three
roles were not launched. The complete negative record is retained.

That run also exposed an uncovered provider route: prepared comparison reasoning
requires two physically admissible candidates, and comparison mode suppresses
Jev's optional escalation. A state with no usable authorized return and one
physically checked candidate requiring approval could therefore never reach
DeepSeek, regardless of the remaining uncapped call budget.

The subsequent `8a55ee69` capability adds an explicitly granted
`authority_gap_reasoning` policy.
It routes only a prepared, fresh, still-open authority gap to the already bounded
orbital reasoning window. It does not choose an action, confer authorization,
change notice data, extend original deadlines, or bypass candidate-bound operator
approval. The model may still wait or finish unresolved. A separate verifier
recomputes route eligibility and budgets. Historical grants without the policy
retain their existing routes and can be verified without upgrading authority.

After focused and production-boundary checks, freeze a new source/protocol in a
fresh output directory and run the same four roles once each, scope first. This
is an in-sample regression of a new routing capability, not a held-out accuracy
or model-superiority study. Preserve the failed predecessor and stop on a failed
role again. The M3 completion requirements above are unchanged.
