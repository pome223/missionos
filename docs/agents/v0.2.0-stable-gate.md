# v0.2.0 stable evidence gate

The v0.2.0 gate keeps three verification dimensions separate for every
required release row:

```text
fixture | live evidence | implementation bound
```

It never reports a single mission-health score. Its process exit code is only
the release decision: a required row with a failed fixture, missing current
live evidence, or unmatched material makes the command return non-zero.

## Semantic binding

Predicate packages bind to their existing canonical package material digests:

- `PX4_GAZEBO_DELIVERY_PREDICATE_PACKAGE_SHA256`
- `NAV2_TURTLEBOT3_PREDICATE_PACKAGE_SHA256`
- `LIBERO_PANDA_PREDICATE_PACKAGE_SHA256`

The parent coordinator and LIBERO observation wrapper now expose equivalent
semantic material digests. They describe sequencing, authority, capture
points, lineage, and denied claims. File bytes are not release bindings, so a
comment or import-order change does not invalidate live evidence.

The first instrumentation and coordinator bindings are explicitly labelled
`matched_post_run_source_audit`: their behavior was present in the pinned live
source archive, but their material digests were defined after those runs and
were not recorded at runtime. A later live run may produce a stronger direct
runtime binding; this gate does not retroactively claim one.

## Version and supersession

The manifest requires at least one current live representative for every
component marked `required_live_evidence=true`. A package version or material
change makes the current record incompatible and produces a typed
`live_evidence_missing_for_current_version` or component mismatch reason.

Historical evidence remains immutable. The selected freshness rejection is
bound to the 2026-07-27 two-second policy and marked `superseded` by the
2026-07-28 three-second policy. It cannot satisfy a current live-evidence
requirement and is not rewritten as evidence for the newer policy.

## Publication records

The public set contains exactly three publication-safe representatives:

1. one live PX4 -> Nav2 -> GR00T/LIBERO parent mission
2. one live MissionOS chat -> GR00T/LIBERO bounded episode
3. one historical typed freshness refusal

The representatives contain no raw task IDs, local paths, credentials, logs,
actions, observations, vendor source, or checkpoint. They retain the digest of
the internal source record without publishing or depending on that internal
file.

## Runtime boundary

CI runs only GPU-free fixtures and evidence checks. It does not start NVIDIA,
Gazebo, LIBERO, an LLM, or physical hardware. A `present` and
`implementation_bound` row means the stored manual evidence remains compatible
with the current semantic material. It does not mean CI repeated the runtime.

Run the gate with:

```bash
python scripts/check_v0_2_0_stable_gate.py --pretty
```
