# 再突入の時刻差診断とレビューの整理

保存済みの模型を変更せず、同じ高度を下降通過する時刻を公開表示と比較した。
既定条件の低高度6点では約508秒の一定差があり、上層では一定差を引いても大きな残差がある。
**これは時刻成分と形状差を分ける事後診断であり、実機への精度検証や原因の同定ではない。**

## 比較対象と計算法

- 対象: `flight14_inspired` の既定profileと、採用しなかったV11較正profile。
- 公開読み取り: `examples/spaceflight/starship-flight14-observations.json` のV17–V25。
  時刻は中継のT+表示、高度基準・計測不確かさ・表示遅延は不明。
- `entry_interface` 後の元のShip保存サンプルから、対象高度を下降通過する区間を探し、
  高度と時刻を線形補間する。CG用補間や画面用に間引いた系列は使わない。
- 元サンプルの時刻は有限・厳密昇順を要求する。上昇中の交差は採らない。
  下降交差がない点、複数回ある点、対象高度に留まる区間は未確定として残す。
  外挿しない。各点の補間区間をJSONに保存する。
- 時刻差は `model_crossing_time - observed_time`。
  V20–V25の全6点に一意で時系列順の下降交差があるときだけ、その中央値を一定差として計算する。
  各点の残差は、その時刻差から中央値を引いた値。
  反跳・途中終了などで区間の終了交差が開始交差より前なら、区間時間・差・比はnullにする。
- V20–V25はこの事後的な整列の**推定に使った点**であり、holdoutではない。
  V11較正時にこれらの点を使わなかったという過去の条件と、今回の診断への使用を区別する。

低6点の中央値は508.378秒、差の範囲は507.029–510.240秒。
70.8→12.9kmは公開表示で742秒、模型で264.791秒。一定の時計移動ではこの区間時間の差は消えない。
2.3→0.1kmは公開表示で30秒、模型で31.341秒。

別実装で生の積分端点からWGS84高度を計算した感度確認では、中央値508.016秒、
100m通過11817.028秒だった。保存サンプルからの補間とは最大約0.55秒違う。
秒の小数表示は計算値の追跡用であり、公開観測や連続飛行の精度を意味しない。

## 採用しなかった較正候補も保持する

以下の「整列後」は、観測時刻に上記の推定差を足して模型の高度を読む事後診断。
軌跡・帰還epoch・制御入力を書き換えた新しい飛行結果ではない。

| 条件 | 低6点の時刻差中央値 | 70.8→12.9km | 元の9点高度MAE | 事後整列した9点高度MAE |
| --- | ---: | ---: | ---: | ---: |
| 既定 | 508.378 s | 264.791 s | 103.034 km | 10.962 km |
| 不採用のV11較正 | 1535.516 s | 259.079 s | 355.346 km | 14.180 km |

355kmへの悪化には大きな時刻差も混ざっていた。事後整列しても候補の残差は既定より大きく、
上層の区間時間は観測の742秒からさらに離れる。衛星遠地点450km上限の不達も別の事実として残る。
比較方法の追加を理由に、元の失敗を成功へ変更しない。

## Claudeレビューで訂正・限定した点

1. V25は11309秒・高度100mの読み取りで、着水時刻ではない。
   模型の実際の `surface_contact` は11830.425秒、速度2.002281m/s。
2. 一定の時刻差から、原因を帰還判断時刻だけに帰属できない。
   公開読み取りには実際の帰還決定・deorbit開始時刻がない。帰還epochの変更は軌道位相や
   突入条件も変えるので、事後の時計シフトとは同じ操作ではない。
3. 低高度6点の近さだけでは最終燃焼、姿勢制御、空力係数、機体生存の妥当性を検証できない。
   上層の差も、揚抗比、弾道係数、突入角、大気のどれが原因か一意には識別できない。
4. 軌道中に一律29km低いとはいえない。V11–V15の平均差は約−28.939kmだが、
   V16では模型273.871km、公開表示271kmで約+2.871km。

## 再現入口と止めどころ

検証済み保存結果に対するread-only診断。既存出力は上書きしない。

```sh
python scripts/analyze_starship_entry.py --input-run output/starship-3d-new-run/study.json --output output/starship-3d-new-run/entry-diagnostic.json
```

CLIは入力ファイルと参照のcontent hashを残すが、入力の真正性や物理モデルを再認証しない。
数値再現の検証は `run_starship_3d.py --verify` の別の境界である。
レポートの追加診断も元studyや保存済みverdictを変更しない。

### Public verification boundary

The public package contains the read-only diagnostic source and fixtures, not
the historical private studies. Generate a fresh compatible 3DOF study before
using the command above. Its output checks interpolation/passage arithmetic,
not model fidelity, authentic flight telemetry, or a new integration.

今回の止めどころは、下降通過・一定差・区間時間を再現し、元の失敗結果と未同定事項を残すこと。
乾燥質量・空力係数・帰還時刻を、この9点へ合わせるために探索しない。
将来、運航者が公表した帰還判断時刻を入力にする場合は、出典を持つ操作入力として固定し、
評価に使う点から分離する。この9点から逆算した508秒を「観測された操作時刻」としない。

## 次段のMissionOS監督

現状は決定的な安全処理と検証がある。LLM提案を受け付ける実行境界はない。

| 判断点 | 実装済み | 未実装 |
| --- | --- | --- |
| 軌道投入 | navigation、高度、降下速度、燃料の固定Rules | 型付き提案、観測鮮度、承認範囲と期限 |
| 放出 | 近地点不足・合成jamで停止 | 待機・再確認・中止の操作契約と復旧モデル |
| 帰還 | scenarioと周回係数から固定した開始時刻 | 実行可能な帰還候補ごとの終端結果と選択 |

5条件は安全制約の回帰試験であり、LLMの価値を示す比較ではない。
navigation vetoは既にRulesが禁止し、永久jamには復旧機構がなく、terminal engine failureにも
監督で救済する候補がない。同じ開始状態から別の合法な行動を実行した結果表がないため、
oracleとの差は**未測定**であり、0とも改善可能とも結論しない。

次はfixtureで `fresh observation → typed proposal → scoped approval → Rules → command receipt
→ independent verification` を分ける。scenario名や未来の故障予定をpolicyへ渡さず、待機中も
力学状態を進め、期限切れ時の動作を定義する。LLM再呼出しではなく凍結した提案・実行ログで
検証できる境界が必要。CLIのsimulation opt-inを認証済み運航者の承認へ昇格させない。
候補で終端結果が変わらない、または単純Rulesがoracleと同等なら、モデル性能比較へ進めない。

この次段は[放出詰まりの有限モデル比較](starship-dispenser-experiment.md)として分離した。
実機に未検証の回復確率や燃料消費を足さず、合成の時間枠と取得済み観測で方針を比べる。
