## 対象と結果

前回の学習済み重みから始め、出力部分・投影画像との対応層に加えて、最後の内部処理ブロックを学習しました。全1,134,100,256パラメーターのうち**47,851,808（4.219%）**、24テンソルが対象です。他の層とVAEは固定しました。2,048回、学習率0.00005、乱数42、バッチ1に事前固定した教師ありの事後学習です。

評価地点は**配送地点より先の開けた場所**に変更しています。前回の狭い通路で残った水面のような表現については、今回の結果では解決したと言えません。飛行経路の拡張や飛行許可も意味しません。

学習用の12地点から24組を新しく収集しました。評価用は新しい4地点・8組で、過去2回に見た全ての入力位置・前進先から最低**19.70 m**離しています。同じ街区内の近い4地点なので、独立した環境への汎化は示しません。評価用の正解画像はGPUへ送っていません。

新しい8組に同じ入力・動作・乱数を与えたとき、平均RGB誤差は **18.35 → 16.46**。数値基準内の画像は **0/8 → 1/8**、停止・前進の両方と目視確認を通過した地点は **0/4**でした。

最低条件は事前に、RGB平均誤差≤15、色成分のどれかが40を超えて異なる画素≤10%、推論≤75秒、経路判断を変える架空の建物や水面がないこととしました。**1地点で停止と2.8 m前進の両方を通ること**を目指し、理想的なRulesへの優越は求めていません。軽微なぼけや質感の差だけでは目視不合格にしません。全8件を残し、判定基準の緩和や評価後の重み選び直しはしていません。[各画像の所見](comparison.json)

前回の狭い通路では数値基準が0/8→3/8に改善したものの、目視を含めた成立地点は0/4でした。その失敗は保持しています。今回と前回では評価場所が違うため、別試験の平均誤差同士を性能向上の証拠として比較しません。今回の前後差にも追加の学習量が含まれ、内部ブロックだけの効果を特定する試験ではありません。

## 次の課題

停止画像では3/4枚で大まかな配置を保てましたが、前進画像は全て形状保持に問題が残りました。次は、APで短く移動した実測RGBD・姿勢履歴と到達画像をGPUなしで整え、動作と形状変化の対応を確認することが必要です。静止履歴、画角、外観の違いのどれが主因かは、この試験では分離できていません。追加GPU試験はここで終了しています。

## 何を確認したか

Gazeboの静止カメラを配置し、16枚の新しいRGBD履歴と、後続の停止画像・2.8 m前進先の画像を収集しました。32組全てが時刻・位置・学習／評価分離の検証を通りました。カメラの配置変更による収集で、APによる実移動ではありません。時間条件の1は1回の指定視点遷移を表し、1秒後の予測を意味しません。

新しい評価位置は街区モデルの建物投影から22.12〜32.29 m、地形上15.46〜15.57 mです。これは点位置の形状確認であり、経路全体の衝突検証ではありません。[形状確認](scene-position-preflight.json)

GPUでは2,048回の実更新、固定部分のハッシュ不変、保存・再読み込み後のテンソル一致、前後16回の実推論を確認しました。別のCPU処理でも、保存した24テンソル全てが開始時から変化し有限値であることを確認しています。[実行条件](protocol.json)・[学習記録](training-receipt.json)・[保存確認](saved-head-audit.json)・[別処理での確認](parameter-change-audit.json)

全体テストは**3,369件成功**、依存ライブラリ警告3件、102.71秒。公開画像の誤差・切り出し・ハッシュはGPUなしで再計算できます。これはGPU学習全体を再実行した検証ではありません。コマンドは[English report](README.md)に記載しました。
