# 横浜：予測と移動後の実観測の比較

**実ANWMの12件すべてが、事前に固定した画像基準を満たしませんでした。** 空の情報を残す修正で投影画像は改善しましたが、生成後には存在しない水面や異なる建物が現れます。実VLA＋WAMによる反復飛行へ進める状態ではありません。

[比較画面](index.html) · [全12画像](contact-sheet.png) · [AP飛行動画](onboard-ap-timelapse.mp4) · [実行前の条件](protocol.json)

今回は、固定候補を使うGPUなしのAP飛行で後続画像を記録し、その後に実WAMでオフライン推論しました。**この試行で実VLAは呼んでおらず、WAM予測を使った飛行もありません。** AP飛行の成功とWAMの評価結果は別の記録です。

## 何を確認できたか

D1・D2で停止中と約2.8 m移動後の画像を取得しました。停止画像は入力の1秒後、移動後の画像は指示地点に到達して停止した直後で、入力からそれぞれ16.248秒・16.748秒後です。後続画像はGPUへ送っていません。移動先は事前の指示のままで、実際に到達した位置から予測対象を作り直してはいません。

移動後のカメラ位置誤差はD1が13.6 cm、D2が10.9 cm、向きの誤差は1.36°・0.30°でした。APは2回の短距離移動、7地点での保持、配送地点での保持、帰還・着陸・disarmを完了しました。動画は元のGazebo機上カメラ273枚、68.25秒、実効約8.87倍速です。荷物の投下や実機飛行ではありません。

最初のAP飛行ではD1の向きが6.48°ずれ、画像比較の対象として不適格でした。磁気センサー設定を調べた後、シミュレーションで既知の発艦方向を離陸前に一度だけPX4へ設定する条件を採用しました。以降はAPの慣性・GNSS推定を使い、真の向きを連続入力していません。これはシミュレーター用の初期化で、実機の方位推定問題や上流の磁気センサー実装を解決したという意味ではありません。途中の離陸前停止・到達不一致も[全7試行](cpu-attempts.json)に残しています。設定と制約は[保守者向け契約](../../agents/yokohama-paired-views.md)に記載しました。

## 予測の結果

元の投影/t4、空の外観を補う投影/t4、同じ補完/t1の3条件を、2地点×2動作で比較しました。補完は過去のRGBと正の無限大深度を持つ上向きの光線だけを使い、既存の有限深度の投影を変えません。補った色を衝突判定や空き空間の証拠にはしません。

補完後の**投影画像**のRGB誤差は1.45〜8.74でしたが、**WAM生成後**は36.64〜58.52でした。D1では一部の誤差が減り、D2では悪化した条件もあります。空が黒く欠けることだけでは、生成の不一致を説明できません。モデルとこの観測条件の適合性、時間設定などの切り分けが残ります。根本原因の一意な特定やWAM品質の修正は未了です。

MAEは224×224の後続実観測に対するRGB平均絶対誤差（0〜255）。`Error >40`は、いずれかの色成分の誤差が40を超えた画素の割合です。事前条件はMAE≤15、同画素割合≤10%、1画像の推論≤75秒。推論は19.6〜20.9秒でしたが、画像条件は全件不合格で、目視でも街区の不一致を認めました。これはこの4組の画像に対する評価であり、一般的な成功率ではありません。Rulesとの性能競争も行っていません。

`t1/t4`はデータセット内のフレーム番号の差を表すモデル条件です。実時間の1秒・4秒との対応は確認できていません。t0による静止画像の再構成を、未来予測の成功とは扱っていません。[ANWMの論文](https://arxiv.org/abs/2512.21887)・[固定した学習データ処理](https://github.com/EmbodiedCity/ANWM.code/blob/657a80268505fa9149c4df502e35aa0f5bce11e5/anwm/data/airvln.py)

## 検証と費用

実行ソースは`20e5c0c2`。全体テスト3,355件成功、依存ライブラリ警告3件。SITL、判断・実行の対応、後続画像の分離を、それぞれ保存済み記録から再検証しました。[検証一覧](checks.json)・[SITL](sitl-verification.json)・[判断と移動](decision-verification.json)・[画像対応](paired-final-verification.json)

GPU上の実行は固定チェックポイント、16フレームの履歴、seed 42、250 diffusion stepsによる12件です。公開画像の誤差とハッシュはGPUなしで再計算できます。

```sh
python docs/examples/yokohama-wam-paired/verify_bundle.py
```

生のセンサーログとクラウド設定は公開物に含めていません。公開物は画像、実行コード、条件、測定値、検証記録、ハッシュです。これだけで生ログ全体の独立検証やGPU推論の完全な再実行ができるという主張はしていません。

今回の追加見積もりは **$0.4348**、累計 **$10.8782 / $15**。請求額は未確定です。所有するGPU VM・ディスクとSITLコンテナーは削除・不在確認済みです。[費用・終了記録](budget.json)

次は飛行の距離を伸ばす前に、この街区に合うWAMの入力・学習条件を、別の観測で確認する必要があります。現条件の予測を配送判断へ使う段階には進みません。海上往復、移動船、強風、10機運用、バッテリー節約は今回の検証範囲外です。
