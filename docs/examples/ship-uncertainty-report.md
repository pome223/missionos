# 予測が不確かな場合の経路判断 — 2026-09-25

**出発時だけ慎重に経路を選ぶ方式は、新規7,560条件で成功を8件増やし、
元の成功を失いませんでした。移動中の再観測から変更を許す方式は、3件の成功を
失いました。** これはCPU上の合成運動と時間予算の比較です。実際の配送や
Step 2全体の達成を示すものではありません。

[前回の比較](ship-dynamic-routes-report.md)では、加速度予測が役立つ条件がある一方、
予測誤差による早すぎる経路変更で多数の成功を失いました。今回は、元の経路で
期限に間に合う予測なら変更を見送り、迂回する場合は減速して止まる動きも含めて
到達可能かを確認する方式を実装しました。

出発時のゲートによる改善は約0.106ポイントです。8件とも観測後も同じ運動が
続く条件でした。予告なしの運動変化がある条件では成功数を増やしていません。
両方式が成功した条件の平均完了時間も約0.039秒長く、速度向上は示していません。

以前の条件も全て残して再計算しました。以前の開発2,160条件は1,740→1,742、
評価2,160条件は1,944→1,950で、出発時のゲートによる既存成功の喪失はありません。
これらは回帰確認です。新規条件も同じ合成世界の構造を使う格子状の比較であり、
独立した飛行試験や学習済みモデルの汎化性能ではありません。

再観測版で失った3件は、いずれも0.1 mの観測誤差がある条件でした。3秒までの
履歴から3.5秒時点で迂回を決め、引き返し3秒も支払いました。その後8秒で
予告のない動きの変化が起こり、迂回路が塞がります。調べた減速仮説は停止後に
その場に留まる動きで、反転する動きを含んでいませんでした。過去に良く合う予測でも、
未来を十分に網羅しているとは限りません。元の経路では3件とも期限内に完了しました。

再観測版は出発時のゲートに対して追加の成功0件、喪失3件でした。2秒待つ方式も
期限の余裕を消費しました。今回の結果から、再観測による変更は採用しません。
出発時のゲートの結果を分けて残し、結果に合わせた閾値の調整はしていません。

全11,880条件を保存し、独立した計算で83,160件の経路結果、判断時刻、集計値を
検算しました。関連テストは73件成功しています。GPU追加費用は0ドルです。

通行直前の確認は全方式とも正確な合成距離を使い、接近・待機・引き返しの場所は
