# 突風で判断を中断し、APの再保持を待つ

**中断・判断の破棄・停止応答は確認できましたが、今回の約9.15 m/sの突風では、再保持して飛行を再開するところまでは未達です。** CPUのPX4/Gazeboで3回検証し、結果をすべて残しました。実VLA・WAM、GPU推論、追加学習は今回は実施していません。

いずれも沖合の船から岸に到達し、岸と市街地入口を含む3/13地点で通常の30秒保持に合格しました。突風によって市街地の判断時の速度上限0.3 m/sを超え、処理を中断。その後もAPのLoiterを維持して再保持を待ちましたが、上表の条件で検証を終了しました。モデルによる移動、荷下ろし、配送完了、帰船は今回の3試験では確認していません。

## 実装した処理

判断中の一時的な速度・位置・向きの変化を、残量不足や位置推定の異常と分けました。一時的な中断では、現在の試行を無効化してAPの保持を続けます。元の位置から0.5 m以内、速度0.3 m/s以下、向きと位置推定が正常な状態で5秒続いたときだけ、別の画像履歴からやり直します。回復待ちは90壁時計秒、判断は最大3試行です。

古い応答・提案・移動許可は再利用しません。停止要求には静止を要求しないため、今回も機体が動いている状態で停止応答を受け取れました。ホスト側の独立した後処理と、所有コンテナーの削除も3回とも確認しました。CPUの実ファイル通信を使う回帰検証では、遅い起動・推論応答の破棄、再開、旧試行からの許可拒否、動いている状態の停止を確認しています。これは実モデル推論やPX4の復帰成功を意味しません。

3 mの回復範囲は1 mの試験とは**別条件**です。判断地点から最大1 mの初期ずれも含めた範囲について、建物との最小余裕20.248 m / 20.399 mを地図で確認しました。通常の30秒保持、再判断前の0.5 m・5秒安定、移動開始後の1 m経路制限、WAMの画像判定は変更していません。停止後に範囲をさらに広げて成功扱いにはしていません。

## 分かったことと未確認のこと

今回の停止理由は、WAMの予測画像ではなく、**判断前に許可した回復範囲を風による移動が超えたこと**です。ただし、範囲を超えた後も待てば戻れたかどうかは、この検証からは分かりません。風の力はGazeboの近似式 `mass × 1/s × (wind velocity − link velocity)` であり、実機の耐風性能や実際の横浜の風を示す結果ではありません。建物による乱流・波・船の動揺も含みません。

記録期間内の風の指令・適用位置・独立した物体による力の検証は3回とも合格しました。ただし最後の突風の終了と、その後の復帰は観測していません。全飛行・貨物の検証は未完了で、風の適用や通常保持3地点の合格とは分けています。記録した通常保持の指標は元の位置記録から再計算し、浮動小数点の差1e-12以内で照合しました。バッテリー表示はSITLの時間ベースの模擬値で、風や推論の消費電力・Whは測っていません。

動画は記録したGazeboのRGBに、残量・風・中断／回復の状態を重ねた8倍速映像です。各映像は297フレーム、残量欠測4フレームを `UNAVAILABLE` と表示します。最後の試験の映像は630.0秒までで、631.916秒の範囲超過そのものは映っていません。最終停止は位置記録とイベントで確認しています。未来の状態を映像に先取りして表示していません。

## 検証と次の場面

全体テスト3,517件成功・2件スキップに加え、最終の回復境界の検証17件を成功確認しました（地図依存を有効化）。飛行に固定したソースは各結果のハッシュに保存しています。最終コードには、その後追加した「回復の起点が承認済みの市街地範囲内にあること」の事前検査があります。この追加検査はCPUで確認しており、今回の全経路を最終コードそのものでもう一度飛ばしたとは扱いません。

追加GPU料金は **$0**。従来の累計見積 **$16.7063 / 上限 $17** は据え置きです。生ログ・画像履歴・各実行時のソースは手元に保持し、公開物には結果・動画・ハッシュを収録しています。

次の自然な場面として、**先行機が配送パッドで荷下ろし中 → 自機が待機 → 退出と空きを再観測 → 荷下ろし、または承認済みの別パッドへ向かう**計画を作りました。[先行機の荷下ろし待ちの計画](../yokohama-pad-queue/PLAN-ja.md)。まず風の課題とは分けてCPUで工程を確認し、その後に固定重みの実モデルを評価する案です。現行WAMの公称1秒の視点予測を、数分後のパッド解放予測としては使いません。追加学習の必要性やモデルによる改善は、まだ示していません。
