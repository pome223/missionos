# 横浜WAM：実際のAP移動履歴による事後学習

**APによる画像・深度・姿勢の収集と帰還着陸は完了しました。実際の移動履歴を使って2,048回事後学習し、評価5件の平均RGB誤差は10.29 → 9.36でした。数値基準は4/5 → 4/5、目視を含む基準は4/5。今回固定した5件すべての成立条件は未達です。** 実VLA＋WAMが操縦する配送飛行の成立は示していません。

## 実際に確認したこと

PX4/Gazeboで市街地入口→角1→角2→配送地点→帰還をAPで飛び、7か所で30秒ずつ保持しました。計測軌跡は1,639点、688.11 m、シミュレーター時間551.224秒です。7保持の最大水平誤差は0.135 m、最大鉛直誤差は0.119 m。帰還・着陸・disarmとコンテナー削除を確認しました。観測接触はなく、標本間を結ぶ経路の中心線と建物との最小距離は7.61 mでした。半径1 mの仮定による形状検査であり、連続した物理接触を完全に証明するものではありません。[SITL検証](sitl-verification.json)

往路の指定区間を4 Hzで収録し、327組の640×360 RGBDと姿勢を保存しました。圧縮は可逆で、深度はfloat32の全ビットを維持します。時刻が連続し、過去の動きから指定した視点と1秒後の実測が位置0.30 m・回転0.05 rad以内で一致した履歴は、前進36件・保持7件でした。重なる履歴は独立した試行ではありません。[全候補と棄却理由](motion-verification.json)

最初の収集は200 MiBの保存上限で停止しました。失敗を残し、可逆な深度圧縮と事前指定した記録区間で再収集したのが今回の成功例です。位置・姿勢の許容差やAPの制御は緩めていません。配送到着直後の記録はまだ姿勢が落ち着く前だったため、保持用の学習データには使用していません。[収集2回の記録](collection-attempts.json)

## 事後学習と予測の評価

学習12件は前進10件・保持2件、評価5件は前進4件・保持1件です。画像の出来を見て選ぶ前に、姿勢の成立状況に基づき分割と評価位置を固定しました。入力は16枚の過去画像・深度・姿勢、予測対象は過去の姿勢から決めた3 m先または保持です。指定対象の位置・過去の全履歴を含む学習／評価間隔は19.78 mで、実測の許容差を差し引いても15 m以上です。テストの未来フレームは、他のテストを含めていずれの入力履歴にも入りません。正解の画像と将来姿勢はGPUに渡していません。[入力検査](input-audit.json)

前回の最終ブロック学習済み重みを継続し、24テンソル・47,851,808パラメーター（4.219%）を更新しました。2,048更新、学習率0.00005、乱数42に固定し、最終更新を評価します。全24テンソルの実変化、固定部分のハッシュ不変、保存・再読み込み後の一致、学習前後計10回の実推論を確認しました。学習時間は230.76秒、モデル処理全体は574.95秒でした。[実行条件](protocol.json)・[実学習記録](training-receipt.json)・[別プロセスによる保存重み確認](parameter-change-audit.json)

合格条件は全5件で、RGB平均絶対誤差≤15、いずれかの色成分の誤差>40となる画素≤10%、推論≤75秒、経路を変える架空の占有形状がないことです。軽微なぼけ・質感差だけでは目視不合格にしません。理想的なRulesを上回ることは要求していません。[各画像の具体的所見](comparison.json)

同じ街区で以前から観測した領域なので、未見都市への汎化とは扱いません。初期重みを含む過去3試験の出典と失敗を残しています。今回の前後比較は同じ入力・動作・乱数を使用していますが、過去の別地点の平均値とは性能比較しません。履歴の変更だけの効果を切り分けた試験でもありません。

「前進3 m」はオフライン予測用の対象であり、モデルがAPに発行した指令ではありません。実際に発行したのは既定AP経路です。モデルの時間入力1を、この実測では+1秒の画像に照合しましたが、任意の速度・環境で1秒後を予測できるという意味ではありません。保持と前進は同じ地点の反実仮想2択ではなく、それぞれ実行済みの別の記録です。

学習前の重みでも数値基準は4/5件でした。今回の追加学習は平均誤差を約9.0%減らしましたが、合格件数は増えていません。特に前進2の左手前の壁は境界が曖昧で、大きな誤差の画素が10.19%あります。基準を10%から緩めたり、このケースを除外したりせず、失敗を残しています。次はこの近い壁の占有境界をどう扱うかを確認し、曖昧な予測で進まず停止できる判断に接続するのが課題です。追加GPU実行は行っていません。

## 検証・予算・次の課題

全体テストは3,389件成功、依存警告3件、106.21秒。公開バンドルの検証器は画像誤差・切り出し・入力分離・保存重みの実行記録・ハッシュをGPUなしで再検証します。生RGBDの全アーカイブと重みは手元に保持しており、公開物だけで学習全体を再実行できるという主張ではありません。正確なコマンドは[English report](README.md)にあります。

今回の追加費用は推定$0.5443、累計**$13.0714／$15**です。請求額は未確定。所有GPU VMとディスクを削除し、不在を確認しました。[終了・費用記録](budget.json)

画像予測の最低成立と、モデルの判断が市街地の複数区間で実際に反映される飛行は別の段階です。後者の合格には、停止・新規観測・モデル提案・Rules確認・AP短区間移動・実到達確認を繰り返す必要があります。今回の学習済み重みは飛行制御に導入していません。海上はAPのみ、市街地だけモデルを使う方針を維持します。

実VLA、モデル制御飛行、荷物の受渡し、海上往復、強風、移動船への帰還、10機運用、実機、省電力は今回未検証です。
