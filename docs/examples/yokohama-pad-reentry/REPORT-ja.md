# 先行機の戻る可能性を使うと、先に待てる条件が2つ増えた

**新しい3場面と到着時刻5通りの判断再生で、進入提案の直後4秒以内に再占有される条件が4件から2件に減りました。** 完全な精度は求めず、この小さい効果を任意の補助判断として残します。

**これは収録映像からの判断検証で、自機の飛行・配送・帰船の比較ではありません。** 使用したのは固定カメラ用の学習済みCPU状態モデルで、実VLA／ANWMではありません。MissionOSの共有判断処理には決定論的な代替処理を使用しています。

## 何を変え、何が分かったか

前段の追加学習で得た重みは固定したまま、認識できた先行機がパッドに近づき、予測の中心位置が4秒以内に6 mの領域へ入る場合に、追加の待機・再観測を提案する接続を加えました。占有ラベルの「不明」は書き換えていません。単に不明なだけ、静止中、退出中、古い予測では待機を増やしません。現在の安全条件を緩めず、進入を許可する権限も作りません。

先に待てたのは中速の到着10秒条件と低速の到着16秒条件で、それぞれ進入提案を34模擬秒遅らせ、先行機が再び退出するまで待ちました。全15条件で最後には進入を提案できました。これは配送の遅延が改善した証拠ではなく、すぐに塞がる進入の提案を2条件で避けた結果です。残る2条件は未達として残します。

新しい154判断時点のうち、現在は進入可能だが4秒以内に再占有される8時点では、4時点で追加待機、4時点は現在Rulesへ戻りました。新しい場面における4秒以内の再占有を伴わない追加待機は0件です。古い記録を再確認した149時点では、再占有を伴わない追加待機が1件ありました。重なり合う判断時点や到着条件を、独立した試行数・成功率として扱いません。

## 記録と検証の範囲

Gazeboで先行機を台本に沿って動かし、固定カメラのRGBと機体位置を実測しました。自機の位置・AP保持・残量は判断再生の代替値です。モデルには過去16枚のRGB、カメラ姿勢、時刻だけを与えています。現在Rulesは実測した先行機位置を使い、5秒の空き観測を要求します。提案、機体側のRules確認、実際の送出は別の事実です。今回の送出は0件です。

新しい評価速度はそれぞれ収録・評価前に固定しました。接続の方針を最初の評価から決めたため、その最初の評価を改修の検証に使い回さず、さらに別の3場面724枚を収録しました。再学習はしていません。 ただし外観、カメラ、経路は共通で、別の場所や見え方への汎化は未検証です。先行機も2台目の自律PX4ではなく、台本で動く物体です。

動画は実測カメラの1倍速再生です。自機を飛ばしていないためバッテリー表示を付けていません。予測・Rules確認の再生は別のUIです。公開検証は画像からの実推論606回と、共有MissionAssuranceAgentから機体側の応答確認まで1212件を再計算・確認します。所有コンテナーは削除済みです。
