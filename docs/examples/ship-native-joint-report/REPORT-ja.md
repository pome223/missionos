# 実VLA＋WAMの配送・帰還と1 km停止原因の修正

追加の沖合1 km固定試行1件で、実VLAと実WAMが同じ飛行に参加し、配送と船への帰還を検証しました。同一実装で4条件すべてを通した結果ではありません。

最終集合のVLAは、市街地入口での短い高度保持移動に限定し、上下提案を約±0.204 mに制約しています。制約のない3次元飛行の検証ではありません。

修正前は沖合100 mの3条件で配送・帰還を検証し、沖合1 kmで配送前に停止しました。元の失敗は保持しています。異なる実装の結果を合算して成功率にはしません。

## 原因と修正

旧処理は、画像全体で暖色の領域を探して主障害物を選んでいました。1 km試行の右5 m候補では、WAMが左端の建物もオレンジ色に描き、中央の柱との識別が曖昧になりました。推論・通信は46.86秒で終わり、75秒の上限内でした。

![元の失敗時の右5 m予測画像](images/right_5m-prediction.png)

柱の色領域は104–147画素（44画素）、左端は0–28画素（29画素）でした。第2領域が最大領域の半分以上あったため、旧処理が拒否しました。入力の形状や投影処理の不正、通信時間超過は直接の停止理由ではありません。

修正版は予測前のRGBD画像から対象の柱を候補視点へ投影し、予測画像内で対応を確認します。実際の位置は生成画像から読み取ります。対象の消失、近傍の複数候補、画像端での切れ、不十分な深度、形状や位置の大きなずれは拒否します。予測後の正解位置を使った対象選びではありません。

位置誤差5 m、推論・通信75秒、出発時の画像鮮度2秒などの合格条件は変更していません。保存済み8枚は開発時の回帰検証に使い、その後の実モデル飛行を別の固定集合として評価しました。ルールとの優劣は評価条件にしていません。

追加の1 km試行でも、右5 m候補には中央103–147画素の柱と、左端0–36画素の領域がありました。同じ保存画像を旧処理へ渡す追加診断では再び曖昧として拒否しましたが、修正版は飛行中に中央の対象を対応付け、その読取りを保存後にも再現できました。旧処理で飛行を再実行した結果ではありません。[同じ予測画像での読取り診断](repaired-parser-diagnosis.json)。

## 途中で見つかったACKの競合

対象識別だけを修正した中間集合では3件を実行し、配送・帰還は3件とも確認しましたが、3件目の全連携検証が不合格になりました。状態サンプルよりACK受信が1.779 ms遅く、実行側が古い状態を採用する競合でした。この集合の連携合格は2/3、予定された1 kmは未実施として保持しています。

実行器がACKの受信時刻を記録し、それ以降の状態サンプルだけを採用する修正を追加しました。独立検証器の条件は変更していません。GPUを使わないPX4/Gazebo配送・帰還確認を通した後、実装段階を分けて実モデルを再検証しました。

[中間集合の結果](association-only-evidence.json)、[ACK時系列の診断](ack-race-diagnosis.json)。

## VLAの出力形式

対象識別とACKを修正した3回目の集合は、100 mの3条件に合格しました。しかし1 kmでは、VLAが`故4924 49</s>`を返し、3つの数値という契約を満たさず停止しました。WAMはこの飛行では未実行です。この集合も3/4の結果として保持しています。

4回目の集合では、生成時の次トークン候補を3つの数値またはLANDという形式に制約するオプションを有効にしました。各値0〜98とLANDはすべて候補に残り、モデルが値を選びます。応答の数値を補ったり、出力後に書き換えたりする処理ではありません。停止・移動範囲・鮮度・衝突制約は維持しています。形式の保証は意味的に正しい行動の保証ではありません。

[3回目の結果](association-ack-evidence.json)、[形式不正の原応答と診断](malformed-action-diagnosis.json)。4回目の出力方針は`aerovla_action_grammar.v1`です。過去の不正応答は拒否のままです。

## 工程に合う移動範囲

4回目の最初の100 m条件では、形式は正常でしたが`55 84 49</s>`（約3.57 mの降下）が出ました。独立した高度制約が拒否し、WAMには進みませんでした。予定4件中1件を実行して合格0件のまま保存しました。

5回目以降は市街地入口の高度保持という工程条件を明示し、生成可能な上下の数値を47〜51（約±0.204 m）へ限定しています。前進・旋回は0〜98、LANDと停止を表す値は引き続き選択できます。値の事後補正はありません。安全判定や到達・配送・帰還の合格条件を緩める変更ではありませんが、モデルの行動範囲を変更した別の実装段階です。

[形式制約のみの結果](format-only-evidence.json)、[降下提案と拒否の診断](phase-action-diagnosis.json)。最終集合の出力方針は`aerovla_inspection_grammar.v1`です。

## 実行許可の数値再現性

5回目は100 mの3件で配送・帰還を確認しましたが、3件目は実行許可の完全一致検査に落ちました。Linuxで生成した座標とmacOSで再計算した座標が最大1.11×10⁻¹⁶ mずれたことが原因です。元のLinux実行環境では元の許可を再現できました。この集合は連携2/3、1 km未実施のまま保持しています。

修正版では導出した位置と時間を小数9桁、方位を小数12桁へ統一し、完全一致の検証と安全条件は維持しました。保存済み入力で新たに生成した許可は実際のLinuxコンテナとmacOSでバイト単位まで一致しました。これは過去の失敗を成功へ変更する操作ではありません。

残り予算では1 kmを固定1試行として事前登録しました。モデルと高度保持の行動範囲は5回目と同じです。最終実装で100 mの3条件を再実行していないため、4条件すべての合格とは扱いません。

[高度保持集合の結果](level-inspection-evidence.json)、[固定条件](level-inspection-protocol.json)、[数値差の診断と両環境照合](precision-diagnosis.json)。

## 100 m・3条件の追加の無料確認

最終実装に対して、5回目の保存記録を使い、100 mの中央・近傍・明確な経路の3条件で許可生成を再計算しました。準備段階と実行段階の計6件が、macOSとネットワークを無効にした実際のLinuxコンテナでバイト単位まで一致しました。追加GPU利用・モデル推論・飛行はありません。

これは数値再現性の確認です。過去の不合格は変更せず、新しい3条件の実モデル飛行が完了したとも扱いません。[無料確認の結果とハッシュ](compact-offline-readiness.json)。
