# 次の場面：先行機の荷下ろしを待つ

配送先Aで先行ドローンが荷物を下ろしており、自機は離れた承認済み待機点に到着します。先行機の真上には入らず、APで保持して再観測します。**次の最小目標は「占有中は待機 → 退出を観測 → 空きを確認 → 荷下ろし → 受領確認 → 帰船」です。** CPUの位置情報と代替判断による配送・帰船を確認しました。[実測レポート](REPORT-ja.md)。実VLA・WAMの画像診断は実施しましたが、この場面での同一飛行評価と追加学習は未実施です。

| 場面 | 判断候補 | 変化の証拠 |
|---|---|---|
| 先行機が荷下ろしを終え、退出準備に入る | Aの待機点で待つ | 荷物と機体の分離、機体の上昇・退出を連続画像で確認 |
| 荷下ろしが長引く、受領できず先行機が残る | 承認済みの代替配送先Bへ向かう | 占有継続、工程の停滞。受領先もBを利用可能と確認 |
| 空いた後に作業者・別の機体が入る | 進入を取り消して再保持 | 最新の占有観測。過去の「空く予定」は進入許可にしない |
| 残量・待機期限に達する | 配送を中止して帰船 | 残量と期限。AIの予測で延長しない |

最初は先行機1機と静止船だけに絞ります。先行機の荷下ろし・離脱を別エンティティとして記録し、配送パッドの占有と進入経路の空きを分けて扱います。その後、退出直前の停止や再占有を追加します。

VLAには工程を踏まえた「待機・代替先」の提案をさせ、APが承認された移動を実行します。現在のVLA接続は短い前進・旋回の出力なので、待機を無理に数値へ読み替えず、工程判断用の出力契約を先に整える必要があります。Rulesはパッド予約、現在の占有、経路、残量を独立に確認します。荷下ろし完了は別の受領記録で確定します。

WAMには将来の退出・占有状態が役立つ可能性があります。ただし、現行WAMは静止世界での行動に応じた視点予測です。入力の公称1秒を、数分後のパッド解放予測としては使えません。過去の飛行ではVLA約17秒、WAM約50秒かかっており、数秒だけの空きを狙う用途には時間が合いません。まず記録映像で、予測対象時刻・観測時刻・応答時刻を結び、実行時には改めて空きを確認する設計にします。

判断の余地を調べるため、推論・判断70秒、Aの待機上限120秒、Bまで90秒、荷下ろし30秒という**仮定**で計算しました。Aが100/140/300秒後に空く設計ケースでは、A待機だけは2/3件、Bだけは3/3件配送できる計算です。状況を完全に知る選択ならB固定より平均25.3秒短縮できます。別の予定90/170/310秒では22.7秒です。これは選択余地の上限であり、飛行結果やモデルの改善値ではありません。[全条件と計算](screen.json)

当初はGPUを使わずにCPUの占有・退出・再占有と工程を確認する方針でした。その後、累計20ドルの承認範囲で[重み固定の実VLA＋WAM画像診断](../yokohama-pad-native-probe/REPORT-ja.md)を実施しました。VLAの待機切替と、WAM入力の照合範囲に課題があり、この場面の実モデル飛行・追加学習は未実施です。今後の比較には現在観測だけの判断、単純な追跡、先行機と通信できる場合の予約・予定時刻も含めます。理想的なRulesを超えることは合格条件にしません。

その後、未来の占有予測が不足ならWAM、工程に合う提案が不足ならVLA、予測が判断へ届いていないなら接続を直します。学習する場合は別の先行機動作・開始時刻を評価用に残し、平均画像誤差だけでなく、配送・帰船、進入取消、待機時間、介入、推論費用で確認します。今回の設計にはモデルの価値や追加学習の必要性を示す結果はまだありません。
