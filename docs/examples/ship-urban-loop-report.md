# 市街地内で判断を更新する制御：GPUなしの検証

市街地内で2回の判断を更新し、各回の移動先への到達を確認してから再観測する
制御を追加しました。今回動かしたのは、CPU上の代替モデル・代替APと、実際の
プロセス起動／終了・HTTP通信です。実VLA/WAMとPX4への接続は未完了です。

| 確認項目 | 観測した結果 |
| --- | --- |
| 正常系 | 新しい入力で2回判断し、異なる選択先への到達を確認 |
| 起動前の制限 | 未承認、海上、工程違い、古い位置では起動を拒否 |
| 実行中の異常 | 入力画像の再利用、別の判断回の応答、危険な候補、Rules拒否、通信失敗、タイムアウト、保持喪失、到達失敗、経路逸脱、海上への逸脱、残量不足を拒否 |
| 終了 | 専用プロセスを終了・回収してから代替APへ帰路を引継ぎ |
| 終了確認の失敗 | 2回の移動が済んでいても帰路への引継ぎを拒否 |
| 遅延応答 | 終了後に過去の応答を再送しても拒否 |

事前に条件とソースのハッシュを固定し、17条件を各1回実行しました。
正常完了1件、想定した拒否16件（未承認1件＋異常15件）で、17件すべてが
期待した結果でした。拒否を配送成功として数えていません。起動した代替モデルの
プロセスは全件で終了・回収しました。[検証記録](ship-urban-loop-evidence.json)

既存の1 km配送・帰船の実モデル結果は、そのまま別の成果として保持しています。
その判断地点は海岸の30 m手前であり、今回の「市街地内だけ」の条件を満たす
結果には数えません。

今回の追加GPU費用は0ドルです。市街地内での実モデル反復飛行、配送・帰船、
機上電源制御、全行程の消費電力削減は、今回の検証では達成していません。
次は実VLA/WAMの入出力とPX4の到達確認をこの制御へ接続し、GPUなしのSITLで
引継ぎを確認してから実モデル飛行へ進みます。

再実行は、リポジトリの依存関係を導入した環境で次のコマンドを使います。
出力先は未作成のディレクトリを指定します。

```sh
python scripts/smoke_ship_urban_loop.py --output-dir /tmp/new-urban-loop-matrix
```
