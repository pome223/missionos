# 先行機を待つための位置・占有の学習

**2026-09-29の追記：** 固定配送先カメラのCPU補助モデルを使う[待機・配送・帰船の一往復](../yokohama-pad-advisory/REPORT-ja.md)を確認しました。実VLA＋ANWMとの同時飛行、機上カメラ対応、任務成績の改善は未確認です。以下は学習時点の記録を保持しています。

**小さなCPUモデルを学習し、新しい動作時刻の3例で「待機→進入を検討」への切替を確認しました。誤った「空き」は0件でした。採用方針を更新し、90%という一律の足切りは使わず、補助判断への組込みを進めます。** ANWM本体の生成画像やVLAを改善した結果ではありません。

[観測と予測を操作する](index.html) · [退出の動画](videos/state-depart.mp4) · [途中停止の動画](videos/state-stall.mp4) · [再進入の動画](videos/state-reenter.mp4)

前回は、[ANWMを追加学習しても予測画像から小さい先行機が消える](../yokohama-pad-learning/REPORT-ja.md)問題が残りました。今回は先行機の位置を画像から直接読み、短い将来の位置と着陸場所の占有を予測する補助モデルを作りました。全体の画質をさらに上げることは目標にしていません。

## 何ができたか

退出・途中停止・再進入を、学習と異なる動作時刻でCPU Gazeboに収録しました。704フレームから155個の画像履歴を作り、0〜4秒先の17時点を採点しています。このうち占有／空きが明確な2,491時点が一致率の分母です。履歴は重複しており、独立した155回の飛行ではありません。

| 新しい3記録での結果 | 実測 |
|---|---:|
| 占有／空きの一致（判別保留も不一致に含む） | **1,999 / 2,491 = 80.2%** |
| 誤った「空き」 | **0 / 占有1,356時点** |
| 判別保留 | 19.8% |
| 画像履歴が適合した割合 | **139 / 155 = 89.7%**（旧実験条件90%。現在の採用条件ではありません） |
| 適合した履歴の位置誤差：0〜4秒平均 / 4秒先 | 0.279 m / 0.570 m |
| 16画像を使うCPU推論：平均 / 95パーセンタイル | 0.036 s / 0.037 s |
| 待機から進入検討への切替 | 3 / 3例 |

位置誤差は適合した139履歴だけの平均です。判別保留を含む一致率とは分母が違います。ゼロ件はこの小規模記録内の結果であり、安全保証ではありません。

再進入の例では、最初は進入検討、約12秒で待機、約49秒で再び進入検討へ変わりました。ただし約51〜54秒は入力不足で保留に戻り、約55秒で復帰します。これは指示の実行ではなく、記録画像に対する助言の変化です。実際に機体を進入させてはいません。

16履歴の保留原因は、履歴内の1画像で先行機候補と別候補の得点差が足りなかったことです。1秒ごとに再観測するため、その画像を含む4回分が保留になります。旧実験条件では6項目中5項目を満たしました。その測定結果と重みは変更していません。今回のユーザー指定により、実験時の90%条件を現在の採用判断から外しました。[詳細な結果](evaluation/evaluation.json)・[保留箇所](diagnostics.json)

## 更新した採用方針

**「入れた方が任務に役立つなら採用する」方針です。** 正解率や入力適合率に一律の90%を求めず、モデルを有効にした場合と無効にした場合で、到達・無駄な待機・手戻り・人の介入などに実用上の利点があるかを見ます。推論や追加の待機にかかる時間・電力・費用も含めて判断します。理想的なRulesに勝つ必要はありません。

今回のモデルは補助判断への組込み対象とします。**現時点では、待ち時間や配送成績が改善した証拠はまだありません。** その効果は次の接続検証で確認します。不確かな観測では、現在観測と独立したRulesに戻して保持・再観測・MissionOSへの照会を行う構成にします。

`evaluation.json` の未達判定は当時の実験結果です。現在の採用方針は別の[採用方針記録](adoption-policy.json)に残しました。飛行への接続が未完了であることと、モデルを90%未達で不採用にすることは分けます。

## 比較と限界

同じ画像から読み取った現在位置を使う比較も残しました。

| 方法 | 占有一致 | 誤った空き | 位置誤差平均 |
|---|---:|---:|---:|
| 現在位置が続く | 86.1% | 0 | 0.692 m |
| 一定速度で動く | 89.7% | 0 | 0.306 m |
| 学習した将来予測 | 80.2% | 0 | 0.279 m |

学習モデルは位置誤差が小さくても、占有一致では単純な比較を上回っていません。学習側には開発記録から求めた誤差幅と占有得点の条件があり、比較側は予測位置の距離だけで分類しています。同じ認識入力による診断であり、同じ不確かさを持つ選択器の比較や、任務成績の改善を示すものではありません。理想的なRulesに勝つことは合格条件にしていません。

対象は**固定カメラ・既知の先行機・既知の通路**です。画像位置から3D位置への対応も、この通路に合わせて学習しています。カメラが移動した場合や機体を見失った場合には使えず、不明を空きに読み替えません。

以前の学習用720フレームを再利用し、以前の評価用752フレームは今回の開発・選択用にしました。新しい記録は重みと基準を固定した後に収録しましたが、外観・街区・経路は同じです。新しい704フレームのうち400フレーム、155履歴のうち61履歴は学習側と画素が同じです。未知の街や機体への一般化は測っていません。

## 飛行へつなぐ前に

動画は固定カメラと動きを指定した先行機の記録で、荷物はあらかじめ置いています。AP保持・荷下ろし・バッテリー・配送帰船は今回検証していません。ANWMやVLAの呼出しもありません。

今の出力は0.25秒間隔の予測点です。その間の衝突や、自機が進入した場合の予測は未確認です。既存の飛行用アダプターが要求する「待つ／進むの両候補」と時間区間の検査は緩めていません。海上はAP、市街地だけモデルを利用する方針も維持します。

次はこのモデルをMissionOSの待機中の補助判断として、実VLA＋WAMと接続します。固定カメラから機上カメラへ移す際の姿勢変化も扱い、補助情報の有無による任務への効果を確認します。承認と実行の責任は既存の仕組みに残します。まず「再観測→待機提案の更新→独立した現在状態の確認」が同じ飛行記録に残ることを目標にします。
