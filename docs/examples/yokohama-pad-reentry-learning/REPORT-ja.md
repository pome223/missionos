# 追加学習だけでは、先行機が戻る前の待機は増えなかった

**CPUモデルを追加学習しましたが、新しい3場面・到着時刻5通りの判断再生で、先行機が戻る前の待機は増えませんでした。** この負の結果を残し、重みの改善だけを任務の効果として扱いません。

**これは収録映像からの判断検証で、自機の飛行・配送・帰船の比較ではありません。** 使用したのは固定カメラ用の学習済みCPU状態モデルで、実VLA／ANWMではありません。MissionOSの共有判断処理には決定論的な代替処理を使用しています。

## 何を変え、何が分かったか

戻る映像240枚を学習に、別の速度の248枚を調整に追加しました。学習時間は約11.3実秒、GPUなしです。学習・調整で選んだ重みを保存・再読込してから、別の戻り速度2場面と退出対照1場面、計716枚を評価しました。

差が出るはずの8判断時点で、既存モデルは7時点の画像履歴が入力条件を満たしませんでした。追加学習後は8時点とも入力条件を満たしましたが、未来の占有ラベルは確定せず、現在Rulesへ戻りました。4秒先の位置の誤差範囲は約2.85 mで、「占有が確実」という条件には厳しすぎます。位置予測が戻る方向を示すことと、占有を確定できることは別でした。

一定速度の比較では15条件のうち1条件で先に待てましたが、追加学習だけでは判断が変わりませんでした。90%の一律条件や理想的なRulesに勝つことを要求して失格にしたのではありません。**学習の改善を待機へつなぐ条件が合っていない**ことが分かったため、次の実験で接続を分けて検証しました。

## 記録と検証の範囲

Gazeboで先行機を台本に沿って動かし、固定カメラのRGBと機体位置を実測しました。自機の位置・AP保持・残量は判断再生の代替値です。モデルには過去16枚のRGB、カメラ姿勢、時刻だけを与えています。現在Rulesは実測した先行機位置を使い、5秒の空き観測を要求します。提案、機体側のRules確認、実際の送出は別の事実です。今回の送出は0件です。

新しい評価速度はそれぞれ収録・評価前に固定しました。古い評価記録は、設計上の診断と回帰確認としてのみ使っています。 ただし外観、カメラ、経路は共通で、別の場所や見え方への汎化は未検証です。先行機も2台目の自律PX4ではなく、台本で動く物体です。

動画は実測カメラの1倍速再生です。自機を飛ばしていないためバッテリー表示を付けていません。予測・Rules確認の再生は別のUIです。公開検証は画像からの実推論602回と、共有MissionAssuranceAgentから機体側の応答確認まで903件を再計算・確認します。所有コンテナーは削除済みです。
