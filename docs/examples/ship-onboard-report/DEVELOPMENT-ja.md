# 試行の分母と修正履歴

比較表は同一コード・ワールドによる最終バッチ V2 のみを使います。
開発4試行、V1 の5試行も別のグループで保存し、好ましくないモデル結果や失敗を置き換えていません。
V1 は6試行を計画しましたが、5試行目の環境設定失敗で停止し、6試行目は開始していません。
V2 は風の反映確認を修正した後、3条件×2手法の全組合せを新規に実行しました。
元の結果ファイルは書き換えていません。

short_clear のVLMは、動作提案と文章では待機を示しながら、構造化された予測秒数に120秒を返しました。
このポリシーが使うのは予測秒数なので、実際には迂回しました。この不整合を後処理で都合よく修正していません。

5試行目では風を1回送った後の読み戻しが期待値と一致しませんでした。
`39ba695` で最大5回の再送・読み戻しを加え、指定した風速と有効状態の両方を実際に観測してから先へ進むように修正しました。
一致しなければ引き続き停止します。ユニットテストで初回不一致後の成功と全試行不一致を検証しています。

## 比較 V2 と保存

V2 の実行コードは `39ba695`。固定した順序・設定・実行ログと全run IDを私用証拠アーカイブに保存します。
4試行目 `96ac66e2d5da455f82f01e26edb9f14f` は離陸上昇中に失敗しました。
ログにIMUの重複時刻エラーがあり、その後PX4の位置推定値は更新されず、Gazeboの機体位置は変化し続けました。
風の設定、市街地の観測・判断、モデル呼出しのいずれにも達する前です。上流のシミュレーター／飛行ランタイム内の根本原因は未解決です。

この失敗を残したまま、未実行の long_block 2試行、続いて short_clear のルール側を最大1回だけ再試行する順序を事前に固定しました。
実行コード・ワールド・ポリシーは変更していません。モデルの不利な結果を入れ替える再試行ではありません。
V2 の全試行を[試行索引](attempts.json)に記録し、所要時間の比較は完了フライトに条件付けています。
したがって、所要時間の表だけから全試行の完了率を判断することはできません。

V2 の結果は[比較JSON](comparison.json)から確認でき、表示用の値は保存画像・PX4ログ・モデル入出力を再検証して生成します。
アーカイブの試行索引は各グループの開始数・保存時ステータス・ファイルハッシュを保持します。
生のログ・ローカル実行パスを含む記録は私用アーカイブに置き、この公開候補レポートには持ち込みません。
