# 犬ロボットに配送を頼む

MissionOSが「会議室Aへ届けて、受領確認後に受付へ戻る」という一つの仕事を
管制する試作です。歩き方や細かな経路追従は、Go2シミュレータ側に任せます。

通常のMissionOSチャットで「会議室Aへ届けて」と入力すると、配送計画が出ます。
`/approve` で承認し、`/run` で開始します。`/status` または「状況」で進行を確認し、
`/cancel` または「中止」で停止を依頼できます。中止の受付と停止確認は別々に表示します。

専用のブラウザ画面でも同じチャット経路を使えます。「送信」のあとに
「承認して配送開始」を押すと、走行映像、受領、帰還の状況が表示されます。
通常配送、片方の通路の閉塞、両方の通路の閉塞を選んで試せます。

「動く障害物を避けて配送」では、赤い障害物が進路を横切ります。
犬側が接近を見て停止し、再開する進路の余裕を確認して配送を続けます。
停止の要求、実際の停止確認、再開がチャットに表示されます。
この短い回避は犬側の制御が行い、LLMの応答を待ちません。

「MissionOS Agentが状況を判断」を選ぶと、通路が塞がった際にAgentが
「待つ・経路を再計画する・未配送のまま受付へ戻る・人に確認する」を判断します。
待機後は通路をもう一度観測します。判断理由は映像の横に表示されます。
最初に承認した範囲内で進めるため、歩行や待機のたびに操作する必要はありません。

```text
配送を承認 → 会議室へ移動 → 受領待ち → 受領確認 → 受付へ帰還 → 完了確認
                 ↓
           通路が塞がった
                 ↓
           停止して状況を判断
                 ↓
       待機・再計画・受付帰還・人への確認
```

屋内の物理シミュレーションで、通常配送、通路を塞いだ場合の迂回、全通路が
塞がれた場合の停止を確認しました。目的地に着いただけでは配送完了にしません。

今回は位置と障害物情報をシミュレータから取得し、受領者も模擬しています。
実物の荷物の積み下ろし、実機での配送は未実装です。配送先は会議室Aに固定した試作です。
依頼の受付は固定の操作に対応し、配送途中の例外判断にLLMを使います。
初期設定は「固定ルールで管制」です。Agentの判断は別途有効化して選びます。受付へ戻れた場合も、未配送なら配送完了にはしません。
