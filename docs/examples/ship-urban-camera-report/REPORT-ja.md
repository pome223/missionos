# 船からの配送：RGB画像から減速を読む

2026-09-25 · Step 2 の画像入力・比較基盤

GazeboのRGBカメラから3条件・計21枚の画像を取得し、画像だけから障害物の
横方向の動きを抽出できた。同じ5枚を4つのルールへ渡し、保存した元画像から
判断を再計算する検証処理まで実装した。
判定は撮影後に、2秒までの画像だけを使ってオフラインで行った。

**[撮影画像と比較レポートを開く](report.html)**

## 同じ画像を見た判断

| 条件 | 速度一定ルール | 減速を考慮するルール | 設計上の最良候補 |
| --- | --- | --- | --- |
| 早く通り過ぎる | 待機 | 待機 | 待機 |
| ゆっくり通過する | 迂回 | 迂回 | 迂回 |
| 減速して途中で止まる | 待機 | 迂回 | 迂回 |

停止する条件では、画像上の動きが小さくなる様子から、減速ルールが迂回を
提案した。速度一定ルールは、そのまま通り過ぎると見積もって待機を提案した。
これらは判断の提案で、今回の処理から機体へ指令は出していない。

## コストの事前評価

| 方法 | 設計上の最良候補との差（3条件平均） |
| --- | ---: |
| 常に待機 | 26.9秒 |
| 常に迂回 | 5.9秒 |
| 速度一定ルール | 6.1秒 |
| 減速を考慮するルール | 0.0秒 |

この表は**解析上の追加コスト**で、実測飛行時間ではない。判断時刻2秒から
障害物が通過するまでの待ち時間を、迂回分170m÷12m/s＋旋回分8秒と比較した。
両候補に共通する飛行時間は除いた。将来の通過時刻は評価側だけで使い、
ルールの入力には渡していない。

単純な減速ルールが3条件とも最良の候補を選んだ。この条件集合では、
WAMによる追加の改善余地はまだ示せない。モデル比較の許可フラグはfalseのまま。

## 実際に確認した範囲

- 640×360の実際のGazebo RGB画像。市街地入口の固定カメラを使用した。
- 各条件で0、0.5、1、1.5、2、4、8秒の画像を取得。判断に使うのは最初の5枚。
  4秒・8秒の画像は判断後の確認用で、選択処理には渡さない。
- 色で合成障害物を追跡し、幾何から求めた位置との最大差は2.38ピクセル。
  この参照位置も検証側だけで使う。
- 条件名・将来情報の混入、画像改変、欠落、時計の不整合、古い画像の流用、
  変更された判断・コード・世界設定を拒否する検証を追加した。
- 新規の関連テスト34件と既存の関連テスト169件が通過。実際のCLI撮影、
  保存先からの再検証、未承認撮影の拒否、コンテナの終了を確認した。

障害物を指定位置へ移してシミュレーション時計を進める撮影であり、連続した
機上映像ではない。色が既知の箱、固定カメラ、既知の奥行きという仮定を使う。
一般的な物体認識、機体運動の補正、奥行き推定は未実装。
今回はPX4飛行、配送・着艦、VLA/WAM、実機を実行していない。

開発時の撮影1回と、固定版の撮影1回を実施した。両方とも取得・比較に成功したが、
反復試験として集計せず、このレポートは固定版1回の21枚を対象とする。
未見条件に対する精度や統計的な優位性は主張しない。
