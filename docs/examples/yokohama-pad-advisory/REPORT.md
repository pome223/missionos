# Live CPU pad advisory through MissionOS to delivery and ship return

One zero-wind PX4/Gazebo flight completed the 1 km offshore leg, city approach, waiting for a preceding actor, independently verified 50 g cargo receipt, ship return, landing and disarming. The frozen CPU image/state model ran 14 times during city pad waiting; 12 forecasts were supported. There were 16 aircraft/MissionOS exchanges, a 31.888 simulated-second wait, and 12.797 m minimum sampled separation. The recorded interval was 1295.548 simulated seconds (4058 observations). Last airborne time-based battery was 64.3%.

[Replay and battery videos](index.html) · [Japanese methods and commands](REPORT-ja.md)

This is a learned **CPU auxiliary state model**, not native ANWM/VLA. The camera is fixed delivery-pad infrastructure, not onboard. Only the last sixteen RGB frames, measured camera poses and timestamps enter the learned predictor. The shared MissionAssuranceAgent uses a deterministic fixture judge and exposes the forecast separately from mission authority. Independent current Rules use Gazebo poses. A forecast can suggest more waiting; it cannot waive observed stable clearance, aircraft hold, reserve, freshness or operator scope. Unknown evidence falls back to current Rules. No 90% aggregate adoption gate was applied, and neither weights nor per-observation validity criteria were changed.

Weights load only during city waiting and are released when waiting ends. Sea warm-up and inference are absent. Post-exit requests and late responses are rejected. A scripted lead actor is not a second autonomous aircraft; the run used no wind and a static ship. Sampled forecasts are neither candidate-action-conditioned nor continuous collision guarantees. The previous negative native ANWM learning result remains unchanged.

The same-observation disabled-advisory counterfactual changed **0 actions**. This is an offline proposal comparison, not a second flight or evidence of improved waiting time, safety, delivery rate or energy. Current-state Rules suffice for this single departure. Optional integration is established; practical mission advantage remains unproven. Future useful evaluation should include a lead returning to the pad, without demanding ideal-Rules superiority or arbitrary accuracy.

Validation: 3,600 tests passed, 2 skipped; actual isolated CPU SITL, actual learned inference, shared judgment and mailbox, independent queue/cargo/full-flight verifiers. Public checking recomputes every image forecast and queue/cargo receipts. Geometry and CPU-isolation checks were run against the original complete archive and their results/source hashes are preserved. Setup failures and an incomplete flight are retained. The first flight collected no eligible histories because images arrived about 0.24 simulated seconds behind the newest pose; after cargo delivery it was deliberately stopped before ship return. A historical measured-pose join corrected the recorder. The next full flight succeeded. Offline recorder diagnostics are separate from mission model usage. The owned container was removed. Incremental GPU cost $0; cumulative estimate $18.5328 of $20. Video battery is timestamp-bound, time-based synthetic telemetry, not Wh, hover or inference power; post-landing rebound is not charging evidence.
