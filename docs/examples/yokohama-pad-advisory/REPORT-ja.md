## 何がつながったか

機体はAPで配送先近くのD3に保持し、先行機の占有をMissionOSへ報告します。固定カメラの直近16枚（4 Hz）、カメラの実測姿勢、時刻だけから補助モデルが4秒先までの位置・占有状態を予測します。先行機の台本や未来位置をモデルへ与えていません。

約2模擬秒ごとに新しい画像履歴で判断を更新します。予測に将来の占有が含まれる場合、追加の待機を提案できます。予測が不明・未取得・古い場合は、現在の観測と独立したRulesへ戻ります。90%の一律合格条件は使いません。海上ではモデルを読み込まず、推論・ウォームアップも行いません。市街地の待機終了時に重みを解放し、終了後の要求・遅い応答を拒否します。

予測を共有のMissionAssuranceAgentへ渡し、その提案を機体側が確認します。進入には、5秒以上の空き観測と最新のパッド・経路状態、保持、残量、時刻・機体同一性、承認範囲の条件が必要です。予測の「空き」だけで進入を許可しません。提案、許可、APへの送出、到達、貨物受領、帰船は別の記録です。

## できたことと残ること

今回で、学習済みCPU補助モデルを含む一往復の接続が成立しました。ただし、同じ観測で補助予測を無効にした判断を再計算すると、行動差は0件でした。これは**同一観測に対するオフラインの判断比較**であり、モデル有無の2回の飛行比較ではありません。待ち時間、安全性、配送成功率、消費電力の改善は示していません。今回の「先行機が一度退出する」条件では、現在の観測による判断でも足ります。モデルの採用は任意の補助として維持します。

固定配送先カメラは既存の学習範囲に合わせた設備です。機上カメラ対応ではなく、モデル入力と動画の説明用カメラも区別しています。先行機は台本で動くGazebo物体で、2機目の自律PX4ではありません。独立した現在状態のRulesにはGazeboの位置を使用しており、実世界の認識系を完成させたものではありません。予測は0.25秒間隔の単一状況のサンプルで、行動候補別・連続時間の衝突予測ではありません。

無風・静止船の1飛行です。高い予測精度や理想的なRulesへの勝利を要求していません。今回の変更では学習済み重みや有効入力条件を調整していません。実ANWMの前回の学習結果も変更していません。次は、退出後に戻ってくる先行機など、未来の予測によって判断を変える余地のある場面で、同じ安全条件の下、必要なときだけ追加学習を検討します。

動画は時刻の前に観測されたPX4残量を重ねています。値は時間ベースの模擬残量で、Whや推論・ホバリングの電力ではありません。着地後の模擬残量の上昇を充電と扱わず、表には着地直前の空中サンプルを使っています。

## 実行と再検証

```sh
python scripts/yokohama_sitl.py --phase flight --approve-sitl --output-dir RUN \
  --sea-round-trip --deliver-payload --occupied-pad --pad-state-advisory assist \
  --timeout-seconds 2400
python scripts/verify_yokohama_pad_advisory.py RUN --output RUN/advisory-verification.json
python scripts/verify_yokohama_pad_queue.py RUN --output RUN/pad-verification.json
python scripts/verify_yokohama_sitl.py RUN --output RUN/verification.json
python scripts/verify_yokohama_payload.py RUN --output RUN/payload-verification.json
python scripts/check_yokohama_pad_advisory.py --bundle docs/examples/yokohama-pad-advisory
```

ローカルテストは3,600件合格、2件スキップ。実ファイル通信、学習済み重みの推論、共有判断処理、古い要求・終了後の要求の拒否を確認しました。公開記録の再検証では画像から全予測を再計算し、待機・貨物の記録を検証します。街区形状とCPU隔離の全飛行検証は元の実行フォルダーで行い、その結果とソースを保存しています。所有コンテナーは終了・削除済みです。

最初の起動はローカルの地理変換ライブラリ不足で飛行前に停止しました。その後の環境構築中にも依存関係不足を確認し、既存の開発環境を変更せず専用環境に補いました。最初の飛行試行では画像が約0.24模擬秒遅れて届き、最新姿勢との照合に失敗したため全照会が履歴不足でした。現在状態のRulesで待機・貨物配送までは進みましたが、モデル推論ゼロを確認したため帰船途中で所有シミュレーターを停止しました。画像時刻以前の実測姿勢を履歴から対応付ける修正後、別の試行で一往復を再実行しました。飛行試行2回のうち成功1回、モデル連携未達・帰船未完了1回です。診断用の静止カメラ収録とオフライン推論も、飛行中のモデル使用とは分けて保存しています。[試行記録](attempts.json)
