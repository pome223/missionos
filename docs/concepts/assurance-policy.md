# 人間が範囲を決め、Assuranceが判断する

人間はYAMLポリシーで、ミッション、守る条件、許す対処、回数の上限を決めます。
内容を確認してその版を承認すると、Assuranceはポリシーと観測に基づいて
Recoveryの対処案がミッションに合っているかを判断できます。

判断後も、Rulesが現在の実行条件とポリシーを検査します。
範囲外、条件が不明、期限切れ、回数超過なら人間へ戻します。
Assurance自身はポリシーを変更したり承認を生成したりできません。

| モード | 実行への進み方 |
| --- | --- |
| `human` | 個別の人間承認を必要とする |
| `shadow` | ポリシー検査結果を記録し、実行は個別の人間承認で進む |
| `bounded` | 承認済みポリシーの範囲内なら個別承認を省略できる |

「人間がこの行動を承認した」と「人間が事前に承認した範囲内で判断した」は、
別々に記録します。承認、実行要求、結果の観測、ミッション完遂もそれぞれ別です。

TurtleBot3では、通常のGatewayミッション実行から、承認済みポリシーによる
復旧の自動続行を利用できます。サーバー側で明示的に有効化し、最初のミッション
承認とポリシーを結び付けます。範囲外や検証できない条件があれば、チェックポイントを
保持して人間へ戻します。PX4への接続は未実装です。

外部モデルやシミュレータを使わず確認できるfixtureの例もあります。
fixtureでの結果と、実際のシミュレータで観測した結果は区別してください。
