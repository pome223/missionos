# MissionOS v0.1.0-rc.2

Release candidate validated on 2026-07-23 for the compound PX4 wind and
obstacle recovery safety boundary. This candidate supersedes `v0.1.0-rc.1`;
the RC1 tag remains immutable as a failed candidate.

## Candidate scope

- Dispatch-time revalidation now rejects `avoid_obstacle` when the latest wind
  exceeds the compiled `max_wind_speed_mps` policy limit.
- Compound recovery dispatch rebuilds and verifies the latest safe-window
  evidence instead of relying only on the proposal-time observation.
- Candidate, compiled request, proposal, and current nearest-obstacle sources
  must all be present and equal, and current local avoidance must still be
  required.
- A compound-hazard transition is completed only when a replacement proposal
  is created. Failed rejudgment is recorded as retryable with a five-second
  backoff.

These checks do not grant approval or dispatch authority. The LLM can propose;
operator approval, rule-constrained dispatch, execution, and verification
remain separate facts.

## E2E / Runtime Verification

The production chat and PX4/Gazebo SITL path was exercised with task
`task_17e5cad54d60` on the public branch. The scenario requested a 7 m/s mean
wind from 90 degrees with a 7 m/s gust and two collision-enabled building-box
obstacles at 50% and 75% of the Tokyo-to-Akihabara route.

The simulator artifacts confirmed both conditions in the same run:

```text
wind_mean_mps=7.0
wind_gust_mps=7.0
obstacles_spawned=2
nearest_obstacle=missionos_route_obstacle_50pct
local_avoidance_required=true
safety_hold_observed=true
```

Source-backed task telemetry was then submitted through the production Gateway
recovery proposal route. The guardrail selected `operator_review`, returned
`proposal_status=guardrail_blocked`, and created no dispatch authority. The run
was ended with an explicit LAND and the final evidence reported landed, ground
contact, and disarmed state. It did not claim route completion, delivery
completion, or physical execution.

This live run covers simultaneous wind and obstacle ingestion, PX4/Gazebo
materialization, Safety HOLD, the production Gateway proposal/guardrail
boundary, and safe termination. It does not claim a successful obstacle
avoidance dispatch.

## Contract and Gateway verification

The full public contract suite passed:

```text
1212 passed
```

New fail-closed cases cover:

- current wind returning above the compiled limit while reachability remains
  otherwise valid;
- latest safe-window evidence becoming invalid before dispatch;
- current nearest obstacle changing after proposal creation;
- local avoidance no longer being required;
- Gateway dispatch returning conflict without queueing a runner request or
  creating authority when the obstacle source changes;
- failed compound rejudgment remaining retryable, respecting backoff, and
  completing only after proposal creation succeeds.

The maintained CI lint boundary, Python compilation, and smoke-inventory check
also passed locally. PR #38 is required to pass its Python 3.11 and Python 3.13
checks at the RC2 commit before the tag is published.

## Limitations

- The live run did not observe the automatic durable compound transition and
  safe-window rejudgment completing. A previously recorded skipped decision
  signature suppressed that later automatic invocation. Dispatch-time wind,
  safe-window, and obstacle-source rejection are therefore proven by contract
  and real Gateway dispatch tests, not by a successful live dispatch.
- The Gateway correctly returned operator review because the candidate did not
  satisfy the complete recovery guardrail; no avoidance maneuver was executed.
- The run used loopback PX4/Gazebo SITL. It is not hardware evidence, delivery
  completion evidence, or permission for physical execution.
