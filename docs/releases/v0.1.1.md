# MissionOS v0.1.1

`v0.1.1` is the first patch release after `v0.1.0`.
It preserves the v0.1.0 backend-neutral Core and two-backend feasibility gate,
while completing already-supported planner and operator-surface behavior.

## Included changes

- DeepSeek can be selected for the planner path without a Gemini or Google
  credential. This selects a model for judgment only; it does not grant
  approval, dispatch, or execution authority.
- A PX4 natural-language recovery request produces a bounded Recovery proposal
  for separate human review. It does not dispatch directly.
- An explicit flight altitude is preserved from Chief Planner input through the
  bounded Mission Designer route. Wind values such as `3m/s` are not parsed as
  altitude.
- Terminal status distinguishes a historical Safety HOLD from a later,
  separately reported dispatch, and treats terrain clearance as not applicable
  after observed landing.

The release continues to preserve the authority split:

```text
LLM judges.
Human approves.
Rules constrain.
Executor acts.
Verifier checks.
Repair loops.
```

## Release verification

The release PR must pass Python 3.11 and 3.13 CI, including the two-backend
Core conformance gate. A public fresh-clone acceptance run is required before
the `v0.1.1` tag is created:

1. install using the README instructions in a clean environment;
2. run the fixture Gateway, CLI, house-map projection, and anonymous replay;
3. confirm no internal dependency, credential, personal path, or private task
   artifact is tracked;
4. run a production-Gateway planning-only CLI request that retains altitude,
   wind, temperature, payload, and obstacle-route constraints.

## Promotion rule

Do not move the immutable `v0.1.0` tag. Create `v0.1.1` only for the exact
merged and acceptance-verified release commit.

## Limitations

- This release is simulator and fixture software only; it makes no physical
  flight, payload-delivery, or hardware-execution claim.
- A planning-only CLI run proves constraint binding, not hosted-model use,
  approval, dispatch, simulator execution, or delivery completion.
